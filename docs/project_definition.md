# EnterpriseFlow Agent 项目定义

## 1. 项目背景

企业内部通常存在规章制度、项目资料、操作手册和任务数据等多种信息。
这些信息可能分散在不同文档和业务系统中，员工查找信息时需要反复搜索，
项目负责人也需要在多个页面中查询和维护任务。

EnterpriseFlow Agent 希望通过统一的后端系统管理企业项目、任务和文档，
并在此基础上逐步加入知识检索和 Agent 工具调用能力。

## 2. 目标用户

系统第一阶段主要面向以下用户：

1. 普通员工：查询企业文档和自己负责的任务。
2. 项目负责人：创建项目、分配任务和查看项目进度。
3. 系统管理员：管理用户、权限和企业文档。

请用自己的语言补充：

- 为什么这三类用户会使用这个系统？
- 他们现在分别面临什么问题？

## 3. 核心问题

本项目希望解决以下问题：

1. 企业文档分散，员工难以快速找到准确内容。
2. 项目和任务信息缺少统一的结构化管理。
3. 普通聊天机器人只能回答问题，无法安全地执行创建任务等业务操作。
4. 大模型回答或执行操作时，缺少来源引用、权限检查和审计记录。

请你从自己的理解中选出最重要的两个问题，并说明为什么重要。

## 4. 第一阶段功能范围

第一阶段暂时不开发 RAG 和 Agent，只实现后端业务基础。

计划实现：

1. 用户管理；
2. 项目管理；
3. 任务创建、分配、查询和状态更新；
4. 企业文档基本信息管理。

第一阶段暂不实现：

1. 大模型对话；
2. 向量检索；
3. Agent 自动调用工具；
4. 前端页面；
5. 复杂的多级权限系统。

## 5. 核心数据对象

系统第一阶段至少包含以下数据对象：

- 用户 User；
- 项目 Project；
- 项目成员 ProjectMember；
- 任务 Task；
- 文档 Document；
- 操作日志 AuditLog。

请你初步写出每个对象需要保存的信息。

例如：

### 用户 User

- 用户编号；
- 用户名；
- 邮箱；
- 密码；
- 用户角色；
- 创建时间；
- 是否启用。

其他对象由你尝试补充。

## 6. 第一阶段验收标准

第一阶段完成后，系统应该能够：

1. 创建和查询用户；
2. 创建项目并添加项目成员；
3. 为项目成员分配任务；
4. 修改任务状态；
5. 保存文档的名称、类型和存储位置；
6. 通过自动化测试验证主要接口；
7. 在数据库中查询到完整的业务数据。
